## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ npm install
```

## API setup

Copy `.env.example` to `.env`, then set `DATABASE_URL` to your PostgreSQL
connection string and replace `JWT_SECRET` with a long random secret. Create the
database before running the migration:

```bash
npm run prisma:generate
npx prisma migrate deploy
npm run start:dev
```

Swagger UI is available at `http://localhost:3000/api/docs`. Register an account
with `POST /auth/register`, then use `POST /auth/login` and authorize with the
returned bearer token. Client and project endpoints require JWT authentication.
Role permissions are initialized by the database migrations and can be managed
by ADMIN accounts under Users & Roles. Permissions are stored per role, module,
and CRUD action; ADMIN retains full access.

The audit log supports paginated filtering through `GET /audit-logs` using
`search`, `entity`, `entityId`, `userId`, `dateFrom`, `dateTo`, `page`, and
`pageSize`. Dates use `YYYY-MM-DD`; `dateTo` includes the full day. Use
`GET /audit-logs/users` to retrieve users present in the audit history and
`GET /audit-logs/export?format=xlsx|pdf|csv` to export all matching results.

The clients API supports `GET`, `POST`, `GET /:id`, `PATCH /:id`, and
`DELETE /:id` under `/clients`. The projects API exposes the same operations
under `/projects`; each project belongs to a client.

## Compile and run the project

```bash
# development
$ npm run start

# watch mode
$ npm run start:dev

# production mode
$ npm run start:prod
```

## Run tests

```bash
# unit tests
$ npm run test

# e2e tests
$ npm run test:e2e

# operational workflows (requires an isolated PostgreSQL test database)
$env:TEST_DATABASE_URL = "postgresql://user:password@localhost:5432/cvpuerta_test"
$env:DATABASE_URL = $env:TEST_DATABASE_URL
npx prisma migrate deploy
npm run test:e2e:operations

# test coverage
$ npm run test:cov
```

The operational E2E suite creates temporary records and removes them after the
test. Set `TEST_DATABASE_URL` to a dedicated test database, never to a
development or production database. The suite covers client/project/production,
purchase order/partial receiving/inventory, consumption/cost history, and
executive profit and margin KPIs.

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.

## Observability

The API provides liveness, database readiness, and process-memory endpoints, JSON request/error logs, and per-response request IDs. See [monitoring.md](./docs/monitoring.md) for probe setup, log fields, and deployment-specific limitations.

PostgreSQL backup creation and restore-drill guidance is in [postgres-backups.md](./docs/postgres-backups.md). The backup script does not configure a scheduler or remote storage.
